Smoke test de Fase 3
0. Pre-requisitos

cd <ruta-al-repo>
git pull                       # traé fase 3 + este script
python scripts/generate_data.py   # si data/raw/ está vacío
1. Levantar todo el stack (nuevo build por el psycopg2-binary agregado)

docker compose up -d --build
Primera vez tarda 5–8 min (rebuild del image de Airflow con Java + Python deps ).

Esperá hasta que todo esté verde:


docker compose ps
Todos los servicios deben decir running y los con healthcheck (healthy).

2. Correr el pipeline end-to-end

docker exec -it aurelia-airflow-scheduler python /opt/airflow/scripts/run_pipeline.py --ds 2024-03-15
Primera ejecución tarda ~2–3 min extra por la descarga de los JARs de Spark (hadoop-aws, aws-java-sdk-bundle, postgresql) al cache Ivy. Vas a ver logs como:

3. Verificaciones
MinIO (http://localhost:9001, minioadmin/minioadmin):

Bucket bronze: 7 subcarpetas (customers, merchants, payments, chargebacks, fx_rates, events, blacklist), cada una con dt=2024-03-15/ conteniendo part-*.parquet.
Bucket silver: mismas 7 subcarpetas, sin partición.
Postgres — conteos por tabla:


docker exec -it aurelia-postgres-dwh psql -U aurelia -d aurelia_dwh -c "SELECT 'dim_customer' AS tbl, COUNT(*) FROM dim_customer UNION ALL SELECT 'dim_merchant', COUNT(*) FROM dim_merchant UNION ALL SELECT 'dim_date', COUNT(*) FROM dim_date UNION ALL SELECT 'fct_payments', COUNT(*) FROM fct_payments UNION ALL SELECT 'agg_daily_kpis', COUNT(*) FROM agg_daily_kpis UNION ALL SELECT 'agg_cohort_ltv', COUNT(*) FROM agg_cohort_ltv ORDER BY 1;"
Esperado aproximado:

Tabla	Rows
dim_customer	500
dim_merchant	50
dim_date	91 (Jan 1 – Mar 31)
fct_payments	~4950–5000 (pueden caer algunos por FX/FK)
agg_daily_kpis	91 (uno por día)
agg_cohort_ltv	6–9 (3 meses de cohorte × 1–3 months_since_signup)
Sample de métricas:


docker exec -it aurelia-postgres-dwh psql -U aurelia -d aurelia_dwh -c "SELECT date_key, total_payments, auth_rate, chargeback_rate, ROUND(gross_volume_usd, 2) AS gross_usd FROM agg_daily_kpis ORDER BY date_key LIMIT 5;"
Esperado: auth_rate alrededor de 0.80–0.85 (nuestro seed usa 82% captured por default) y chargeback_rate alrededor de 0.03–0.05.

4. Test de idempotencia (el más importante)

docker exec -it aurelia-airflow-scheduler python /opt/airflow/scripts/run_pipeline.py --ds 2024-03-15
Correlo dos veces. Los conteos de Postgres deben ser exactamente los mismos (no debe duplicar rows). Ese es el criterio de "idempotencia" que pide el PDF.

5. Cleanup
Si querés borrar todo y empezar de cero:


docker compose down -v
Cosas que pueden fallar y qué mirar
Síntoma	Causa probable	Fix
Timeout descargando JARs de Spark	Sin internet en el container o corta iterable	Reintentar; los JARs caché en /home/airflow/.ivy2/
Connection refused a minio:9000	MinIO no healthy todavía	docker compose ps, esperá
FATAL: password authentication failed for user "aurelia"	.env difiere del compose default	Chequeá .env
payments.csv not found	Seed no corrió	python scripts/generate_data.py local
Rows duplicadas en re-run	Bug de idempotencia en gold_marts	avisame el output exacto
